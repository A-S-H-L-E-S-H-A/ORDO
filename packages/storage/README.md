# ORDO Storage

This package provides ORDO's PostgreSQL storage layer with SQLAlchemy 2.x, Alembic, asyncpg, and pgvector. It targets one Neon database with four schemas and 25 application tables.

## Architecture and folder layout

- `src/ordo_storage/` – shared declarative base, async session utilities, configuration, and models
- `alembic/` – one schema-aware migration environment and ordered revisions
- `scripts/` – database and live table-inventory checks
- `.env.example` – safe local configuration template

The required schemas are `github` (14 tables), `code_intelligence` (4), `ml_analysis` (6), and `application` (1). The six initial revisions create these tables; the following metadata-alignment revision adds the missing stable-ID uniqueness constraints and reconciles indexes without changing the table inventory. Alembic also maintains its `alembic_version` table outside this application-table count.

Dependencies: SQLAlchemy 2.x, Alembic, asyncpg (runtime), psycopg2-binary (synchronous Alembic connection), pgvector, Pydantic Settings, and python-dotenv. Alembic autogeneration is restricted to the four ORDO schemas so unrelated database schemas are not treated as application tables.

## Install

```powershell
python -m pip install -e packages/storage
```

## Environment variables

Configure these values in the process environment or an approved local secret store. A local `packages/storage/.env` may be used only when authorized; never commit it. The runtime URL must be Neon’s pooled URL and the migration URL must be its direct/unpooled URL. The runtime configuration normalizes PostgreSQL URLs for asyncpg and Neon SSL.

```env
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST/DATABASE?ssl=require
DATABASE_URL_UNPOOLED=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
```

## Database checks

```powershell
python packages/storage/scripts/check_database.py
python packages/storage/scripts/verify_tables.py
```

The checks query the configured database, not ORM metadata. The table check requires an exact match for all 25 application tables and exits non-zero for either missing or unexpected tables. The database check also requires all four schemas and the `vector` extension.

## Embeddings

ORDO's database and code-retrieval documentation does not approve an embedding model, version, or dimension. The embedding columns therefore use dimension-flexible pgvector `VECTOR` types rather than guessing a fixed size. This permits storing vectors of different dimensions, but prevents the usual HNSW/IVFFlat indexes on an untyped-dimension column. No ANN vector index is created; approve a model and dimension before adding dimension-specific indexes or semantic-search behavior.

## Generate a migration

```powershell
alembic -c packages/storage/alembic.ini revision --autogenerate -m "describe the change"
```

## Apply migrations

```powershell
alembic -c packages/storage/alembic.ini upgrade head
```

## Current Alembic revision

```powershell
alembic -c packages/storage/alembic.ini current
```

## Verify tables

```powershell
python packages/storage/scripts/verify_tables.py
```

## Future migration workflow

Review autogenerated migrations manually, test them against an isolated PostgreSQL database, and use the direct Neon URL for approved migration runs. Check `alembic current` after applying revisions. Do not use an automatic production downgrade; some migration downgrades delete data.

## Security notes

- Never commit `.env` files or connection strings.
- Do not print passwords or unredacted connection URLs.
- Do not create a local secret file without authorization; prefer the process environment or an approved local secret store.
- Keep Neon credentials out of source control and logs.
